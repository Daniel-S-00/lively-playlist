# Lively Playlist

[![Latest release](https://img.shields.io/github/v/release/Daniel-S-00/lively-playlist?label=download&color=007ACC&logo=github)](https://github.com/Daniel-S-00/lively-playlist/releases/latest)
[![License: MIT](https://img.shields.io/badge/license-MIT-007ACC.svg)](LICENSE)

A Windows tray app that adds **playlist** functionality to
[Lively Wallpaper](https://github.com/lively-community/lively) — curated groups of
wallpapers that rotate on a timer, per monitor.

Lively itself has no playlist feature. This app fills that gap **externally**: it drives
Lively over its own IPC API and does not modify or fork Lively.

> **[Download the latest release →](https://github.com/Daniel-S-00/lively-playlist/releases/latest)**
> Grab `LivelyPlaylist.exe` and double-click it — no install, no .NET runtime required.

## Features

- **Playlists** — multiple named playlists; each has its own wallpaper selection,
  interval, and mode. Switch from the window or the tray menu.
- **Rotation modes** — `Sequential` (ordered) or `Shuffle` (Fisher-Yates bag: no
  wallpaper repeats until every one has played).
- **Per-monitor** — every connected display gets the same sequence, offset so screens
  differ; an optional per-monitor random mode is available in config.
- **Live editing** — interval, mode, and playlist selection apply immediately; a file
  watcher reloads `playlist.json` when you edit it by hand.
- **Library auto-detect** — new wallpapers added to the Lively library are picked up
  without a restart.
- **Thumbnail preview** — select a row to preview it; a countdown shows time to the next
  change.
- **Start with Windows** — optional (HKCU Run key, no admin) plus optional auto-start
  when Lively is detected. Launches minimized to tray either way.

## Requirements

- Windows 10/11, **x64**
- [Lively Wallpaper](https://github.com/lively-community/lively) installed — its core
  process hosts the IPC server this app talks to, so it must be running.

## Usage

1. Start Lively Wallpaper.
2. Run `LivelyPlaylist.exe`. It starts **minimized to tray** — no window.
3. Double-click the tray icon to open the control panel.
4. Pick a playlist (or create one), choose interval/mode, check your wallpapers, then
   **Save Playlist** → **Start**.

`playlist.json` and `lively-playlist.log` are created next to the executable. Both are
writable from the UI, and the log is openable from the tray menu.

> If the picker shows "no wallpapers found", Lively isn't reachable or has no wallpapers
> imported. Check the log.

## Building from source

```powershell
# Stop any running instance first — it locks the .exe and the build will fail.
Get-Process -Name LivelyPlaylist -ErrorAction SilentlyContinue | Stop-Process -Force

& "$env:ProgramFiles\dotnet\dotnet.exe" build .\LivelyPlaylist.csproj -c Debug
```

- SDK: **.NET 10** (`net10.0-windows`, WinForms). `dotnet` may not be on `PATH` — use the
  full path.
- **Publishing a portable exe** (bundles the runtime, no .NET install needed by the user):

  ```powershell
  & "$env:ProgramFiles\dotnet\dotnet.exe" publish .\LivelyPlaylist.csproj `
      -c Release -r win-x64 --self-contained true `
      -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true
  ```

### Changing the icon

The icon is `Assets\LivelyPlaylist.ico` (7 sizes: 16–256), wired as `<ApplicationIcon>`
in the csproj and as an `EmbeddedResource` loaded by `AppIcon.cs` for the tray. To change
it, overwrite that `.ico` and **delete `bin/` and `obj/` first** — a plain `dotnet build`
reports "up-to-date" and will not re-embed a changed `.ico`, so the old art stays baked in.
(Explorer's icon cache may also need a refresh — log off/on or `ie4uinit.exe -show`.)

## How it works

```
LivelyPlaylist (this app)
   │  gRPC over Windows named pipes
   ▼
Lively.exe core process
```

Transport is `GrpcDotNetNamedPipes` (`NamedPipeChannel`) — **not** TCP, which is why this
is C#: a non-.NET client can't easily speak the protocol. The pipe name mirrors Lively's
`SingleInstance` constant: `Grpc_LIVELY:DESKTOPWALLPAPERSYSTEM{username}`.

Proto files in `Protos/` are **copied from the Lively source** and code-generated by
`Grpc.Tools` — Lively's assemblies are not referenced. Source of truth:
<https://github.com/lively-community/lively> → `src/Lively/Lively.Grpc.Common/Proto/`.

Two behaviors worth knowing if you touch the code:

- `DesktopService.GetWallpapers()` returns only **currently active** wallpapers, not the
  library. The full library lives on disk, so `LivelyClient.GetLibraryAsync()` scans
  `{WallpaperDir}/wallpapers/` and reads each `LivelyInfo.json`. When `wallpaper_dir` is
  empty in Lively's settings, it falls back to Lively's own default
  (`%LocalAppData%\Lively Wallpaper\Library`).
- `LivelyInfo.json`'s `Type` field is an **integer** (enum), not a string.

See [AGENTS.md](./AGENTS.md) for full architecture notes and the gotchas list.
